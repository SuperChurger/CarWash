2.1. Модель сценариев использования предметной области
	Ключевыми акторами в модели сценариев использования разрабатываемой системы управления очередью на автомойке самообслуживания являются Пользователь и Администратор. Акторы взаимодействуют с системой через определённый набор прецедентов, отражающих их обязанности и зоны ответственности.
	Пользователь является основным актором системы и использует сервис для минимизации времени ожидания и упорядочивания процесса мойки. Его функциональность охватывает все действия, связанные с участием в очереди: регистрация и аутентификация по номеру телефона, создание записи на мойку (в живую очередь), просмотр текущего статуса очереди (свой номер, количество человек впереди, примерное время ожидания), отмена записи или выход из очереди, подтверждение фактического начала и окончания мойки. Кроме того, пользователь имеет доступ к истории своих моек и личному рейтингу. Пользователь не имеет возможности просматривать данные других клиентов, изменять настройки очереди или получать административную статистику, что обеспечивает разграничение прав доступа и защиту персональных данных.
	Администратор отвечает за мониторинг и поддержание корректной работы системы. Его зона ответственности включает просмотр загруженности моек (количество записей на каждый бокс), анализ общей статистики по записям (среднее время ожидания, пиковые часы загрузки), просмотр данных пользователей (общее количество моек, текущий рейтинг) и при необходимости изменение рейтинга конкретного пользователя вручную. Администратор не участвует в очереди как обычный клиент — его действия направлены на контроль работы сервиса и при необходимости коррекцию поведения пользователей через механизм рейтинга. В рамках системы действия администратора могут логироваться для обеспечения прозрачности.
Оба актора получают уведомления о значимых событиях через систему нотификации: пользователь — о приближении его очереди, об успешной регистрации, подтверждении начала/окончания мойки; администратор — о нештатных ситуациях (например, превышение времени ожидания в очереди). Это обеспечивает оперативность взаимодействия без необходимости постоянно обновлять веб-страницу.

2.2. Логическая модель данных
Мойка (CarWash) — автомойка самообслуживания, имеющая несколько боксов. Содержит уникальный идентификатор, название, адрес и режим работы (например, «08:00–22:00»).
Бокс (Box) — отдельный пост мойки, принадлежащий конкретной мойке. Характеризуется уникальным идентификатором, номером бокса (1, 2, …), статусом («свободен», «занят», «на обслуживании») и ссылкой на мойку-владельца. Одна мойка может иметь несколько боксов (связь один-ко-многим), каждый бокс принадлежит только одной мойке.
Пользователь (User) — зарегистрированный клиент или администратор системы. Атрибуты: уникальный идентификатор, номер телефона (логин, уникален), хэш пароля, целочисленный рейтинг (неотрицательный), роль («клиент» или «администратор»), статус учётной записи («активна» или «заблокирована»), дата регистрации и дата последнего входа. Администратор имеет доступ к управлению любой мойкой в системе.
Запись в очередь / на время (QueueEntry) — фиксирует участие пользователя в очереди конкретной мойки. Атрибуты: идентификатор, тип записи («live» — живая очередь, «scheduled» — запись на конкретное время), ссылки на пользователя, мойку и бокс (бокс заполняется при начале мойки). Статус записи: «ожидает» (waiting), «активна» (active), «завершена» (completed), «отменена» (cancelled), «покинул» (left). Для типа «live» хранится дата и время создания записи. Для типа «scheduled» — желаемые дата и время начала, а также продолжительность мойки (в минутах). Для всех записей фиксируются фактическое время начала и окончания мойки.
История моек (WashHistory) — архив завершённых моек. Содержит идентификатор, ссылки на пользователя, мойку и бокс, время начала и окончания мойки, а также значение рейтинга пользователя на момент мойки. Заполняется автоматически при завершении записи.
Журнал изменения рейтинга (RatingLog) — обеспечивает аудит всех операций, влияющих на рейтинг пользователя. Атрибуты: идентификатор, ссылка на пользователя, старое значение рейтинга, новое значение, причина изменения («автоматически за начало», «автоматически за окончание», «ручная корректировка администратором»), дата и время изменения. Для ручных корректировок дополнительно указывается идентификатор администратора, выполнившего действие.
Связи и ограничения целостности данных:
•	Пользователь может иметь только одну активную запись (со статусом «ожидает» или «активна») в любой момент времени во всей системе. Это предотвращает возможность одновременного участия в очереди на разных мойках или создания нескольких бронирований.
•	После завершения, отмены или выхода из записи пользователь может создать новую запись.
•	Одна мойка может содержать много записей, каждая запись относится только к одной мойке.
•	Мойка и бокс связаны один-ко-многим: бокс не существует без мойки.
•	Бокс может быть связан не более чем с одной активной записью (статус «активна») в каждый момент времени. Если запись не назначила бокс заранее (для «scheduled» с выбором бокса при начале), проверка занятости бокса выполняется в момент начала мойки.
•	Для записей типа «scheduled» необходимо обеспечивать непересечение временных интервалов на одной мойке: клиент не может записаться на время, которое уже занято другим клиентом. Если в записи указан конкретный бокс, дополнительно проверяется его занятость на это время.
•	Завершённые записи (статус «completed») переносятся в историю моек (WashHistory), после чего исходная запись может быть помечена как архивная или удалена по политике хранения.
•	Все изменения рейтинга обязательно регистрируются в RatingLog.
•	Номер телефона пользователя уникален.
•	Рейтинг не может быть отрицательным.
•	Статусы и типы записей принимают только указанные наборы значений.

2.3.Структурное моделирование системы

Клиентская часть реализована в виде веб-приложения, адаптированного для мобильных устройств и персональных компьютеров. Она включает следующие функциональные модули:
• Модуль аутентификации (клиентский) — обеспечивает интерфейс регистрации и входа по номеру телефона, ввод одноразового кода подтверждения, отображение ошибок при неверных данных и информации о блокировке аккаунта.
• Модуль просмотра и бронирования слотов — отображает календарь и сетку доступных слотов с цветовой индикацией (свободен / занят / недоступен по рейтингу), обрабатывает выбор слота и отправляет запрос на бронирование на сервер.
• Модуль управления записями — отображает список текущих и прошлых записей клиента, предоставляет возможность отмены записи с учётом штрафных правил, а также кнопки подтверждения начала и завершения мойки в установленные временные окна.
• Модуль профиля и рейтинга — показывает текущий рейтинг клиента, историю завершённых моек и историю изменений рейтинга с указанием причин.
• Модуль административного интерфейса — предоставляет панель управления боксами (добавление, редактирование, отключение), настройку расписания и перерывов, просмотр всех записей с фильтрацией по дате, боксу и клиенту, формирование отчётов (загрузка боксов, неявки, рейтинг клиентов), а также ручную корректировку рейтинга и установку блокировок.
Серверная часть построена на платформе ASP.NET Core MVC и включает следующие функциональные модули:
• Модуль аутентификации и авторизации — обрабатывает регистрацию и вход по номеру телефона с подтверждением через одноразовый код, управление сессиями и JWT-токенами, разделение прав доступа между клиентами и администраторами, временную блокировку учётной записи при многократных неудачных попытках входа.
• Модуль управления очередью и записями — реализует бизнес-логику работы с живой очередью и записью на конкретное время: проверка доступности слотов с учётом рейтинга клиента, защита от двойного бронирования, контроль ограничения «не более одной активной записи на пользователя», обработка отметок о начале и окончании мойки с контролем временных окон (15 минут на начало, 1 час на завершение), автоматическая фиксация неявок.
• Модуль рейтинга и логирования — автоматически изменяет рейтинг клиента (повышение за успешное подтверждение начала и окончания мойки, понижение за неявки, поздние отмены или неподтверждение завершения), инициирует временную блокировку при трёх последовательных неявках, ведёт журнал всех изменений рейтинга с указанием причины, времени и идентификатора администратора при ручной корректировке.
• Модуль администрирования — предоставляет API для управления боксами (CRUD), настройки глобальных параметров работы мойки (время работы, длительность слота, пороги рейтинга, перерывы), получения отчётов в формате CSV, ручной корректировки рейтинга любого клиента и установки временных блокировок.
• Модуль уведомлений — отправляет клиентам уведомления о приближении очереди, успешной регистрации, подтверждении начала/окончания мойки, а администратору — о нештатных ситуациях (например, превышение времени ожидания в очереди).

2.4. Модель классов предметной области
Класс User представляет пользователей системы — зарегистрированных клиентов и администраторов. Он содержит учётные данные (уникальный номер телефона, хэш пароля), целочисленный рейтинг (неотрицательный), роль («клиент» или «администратор»), статус учётной записи («активна» или «заблокирована»), а также временные метки регистрации и последнего входа. Класс User связан с классом QueueEntry: один пользователь может создавать множество записей, однако в любой момент времени может иметь не более одной активной записи (со статусом «ожидает» или «активна»). Пользователь также связан с классом WashHistory: одному пользователю соответствует множество завершённых моек в архиве. Кроме того, класс User связан с классом RatingLog: каждое изменение рейтинга пользователя фиксируется в журнале, при этом при ручной корректировке указывается идентификатор администратора, выполнившего действие.
Класс CarWash представляет автомойку самообслуживания как объект автоматизации. Он содержит уникальный идентификатор, название, адрес и режим работы. Мойка связана с классом Box отношением один-ко-многим: одна мойка может включать несколько боксов, каждый из которых принадлежит только одной мойке. Также мойка связана с классом QueueEntry: на одну мойку может приходиться множество записей, каждая из которых относится только к одной мойке.
Класс Box описывает отдельный пост мойки. Он характеризуется уникальным идентификатором, номером бокса, статусом («свободен», «занят», «на обслуживании») и ссылкой на мойку-владельца. Бокс связан с классом QueueEntry: один бокс может фигурировать в нескольких записях, но в каждый момент времени не более чем в одной активной. Кроме того, бокс связан с классом WashHistory: каждая завершённая мойка в архиве привязана к конкретному боксу.
Класс QueueEntry фиксирует участие пользователя в очереди конкретной мойки. Он содержит идентификатор, тип записи («live» — живая очередь, «scheduled» — запись на время), статус («ожидает», «активна», «завершена», «отменена», «покинул»), временные метки создания, фактического начала и окончания мойки, а также для записей по расписанию — желаемое время начала и продолжительность. Запись связана с классами User, CarWash и Box отношениями многие-к-одному: каждая запись принадлежит одному пользователю, одной мойке и одному боксу. При завершении мойки данные записи переносятся в класс WashHistory.
Класс WashHistory представляет архив завершённых моек. Он содержит идентификатор, ссылки на пользователя, мойку и бокс, фактическое время начала и окончания мойки, а также значение рейтинга пользователя на момент мойки. Класс заполняется автоматически при переводе записи в статус «завершена» и обеспечивает долгосрочное хранение истории операций.
Класс RatingLog обеспечивает аудит всех операций, влияющих на рейтинг пользователя. Он содержит идентификатор, ссылку на пользователя, старое и новое значение рейтинга, причину изменения («автоматически за начало», «автоматически за окончание», «ручная корректировка администратором»), дату и время изменения. При ручной корректировке дополнительно фиксируется идентификатор администратора. Один пользователь может иметь множество записей в журнале.
Класс Slot описывает фиксированный временной интервал, на который клиент может забронировать бокс. Он содержит идентификатор, ссылку на бокс, дату и время начала, длительность в минутах и статус («свободен», «забронирован», «заблокирован»). Слот связан с классом Box отношением многие-к-одному: один бокс имеет множество слотов, каждый слот относится к одному боксу. Для записей типа «scheduled» слот связывается с QueueEntry, при этом один слот может быть забронирован только одним клиентом.
Класс SystemSettings содержит глобальные параметры работы мойки, задаваемые администратором: время начала и окончания рабочего дня, длительность слота, временные окна для отметок о начале и завершении мойки, пороги рейтинга для приоритетной записи, количество неявок для автоматического бана и срок блокировки. Класс является синглтоном в рамках системы и не имеет прямых ассоциаций с другими классами предметной области, однако определяет правила функционирования модулей управления очередью, рейтингом и администрирования.

Сущность «Мойка» (CarWash) содержит информацию об автомойке: уникальный идентификатор, название, адрес и режим работы. Одна мойка может иметь несколько боксов.

Сущность «Журнал рейтинга» (RatingLog) фиксирует все изменения рейтинга пользователей: старое и новое значение, причину («автоматически за начало», «автоматически за окончание», «ручная корректировка»), дату и время. При ручной корректировке указывается идентификатор администратора-инициатора. Связь: один пользователь может иметь множество записей в журнале.

Все связи реализованы через внешние ключи. Диаграмма наглядно демонстрирует, что пользователь может иметь только одну активную запись в системе, а бокс — не более одной активной записи в каждый момент времени. Завершённые записи перемещаются в историю, а рейтинговые изменения полностью логируются.

Модель классов описывает основные объекты системы управления очередью на автомойках самообслуживания, их атрибуты, методы и взаимосвязи, необходимые для реализации функциональных требований.

Класс CarWash представляет автомойку. Содержит атрибуты: Id (уникальный идентификатор), Name (название), Address (адрес), WorkingHours (режим работы). Методы: GetBoxes() — получить список боксов, UpdateSchedule() — обновить расписание.

Класс Box описывает бокс мойки. Атрибуты: Id, CarWashId (ссылка на мойку), BoxNumber (номер), Status (перечисление: Free, Occupied, Maintenance). Связь с CarWash — композиция (бокс не существует без мойки). Методы: ChangeStatus() — изменить статус, IsAvailable() — проверить доступность.

Класс User представляет зарегистрированного пользователя. Атрибуты: Id, PhoneNumber (уникальный логин), PasswordHash, Rating (целое, >=0), Role (перечисление: Client, Admin), AccountStatus (Active, Blocked), RegistrationDate, LastLoginDate. Методы: Authenticate(), UpdateRating(), Block(). Администратор наследует этот класс или использует роль; для простоты роли реализованы через перечисление.

Класс QueueEntry — центральный класс для управления записью в очередь. Атрибуты: Id, Type (Live, Scheduled), UserId, CarWashId, BoxId (может быть null), Status (Waiting, Active, Completed, Cancelled, Left), для Live — CreatedAt, для Scheduled — DesiredStartTime, DurationMinutes, а также ActualStartTime, ActualEndTime. Методы: ConfirmStart() — отметить начало мойки (проверяет временное окно 15 минут), ConfirmFinish() — отметить окончание (окно 1 час), Cancel() — отменить запись (со штрафом при отмене менее чем за 15 минут), Leave() — выйти из живой очереди. Ограничения: у одного пользователя может быть не более одной активной записи; бокс может быть занят только одной активной записью.

Класс WashHistory хранит архив завершённых моек. Атрибуты: Id, UserId, CarWashId, BoxId, StartTime, EndTime, RatingAtMoment. Метод: ArchiveEntry() (вызывается автоматически при завершении записи).

Класс RatingLog обеспечивает аудит изменений рейтинга. Атрибуты: Id, UserId, OldValue, NewValue, Reason (AutoStart, AutoFinish, Manual), ChangeTime, AdminId (опционально). Метод: LogChange() — фиксирует изменение.

Класс AdminService (или методы в классе User с проверкой роли) предоставляет административные функции: ManageBoxes(), ViewAllBookings(), AdjustRating(), GenerateReports().

Основные связи между классами:

User (1) — QueueEntry (0..*): один пользователь может иметь несколько записей, но не более одной активной.

CarWash (1) — Box (1..*): одна мойка включает много боксов.

CarWash (1) — QueueEntry (0..*): одна мойка содержит много записей.

Box (0..1) — QueueEntry (0..1): связь «один-к-одному» для активной записи (бокс может быть занят или свободен).

User (1) — WashHistory (0..*): один пользователь имеет много записей в истории.

User (1) — RatingLog (0..*): один пользователь имеет много записей в журнале рейтинга.
